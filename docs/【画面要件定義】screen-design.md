## 目的と適用範囲

キーワード調査・分析・選定からペルソナと記事制作方針を整理し、新規タイトルを検討する。公開済み記事では、本文・対象キーワード・検索順位・上位タイトルを照らしてタイトルを改善する。

基準は「【要件定義】AI記事作成ジェネレーターVer4.html」。作業途中の内容は永続保存せず、生成成功時の履歴だけを永続保存する。入力上限、利用回数、本文を履歴に保存しない条件は要件定義に従う。記事本文の自動生成・記事の保存管理は将来機能とする。

## 共通構成と移動方法

| 位置 | 表示・動作 |
| --- | --- |
| ヘッダー | アプリ名と「履歴 n件」。nは実際の保存件数。履歴画面で最大20件保存と説明 |
| モード切り替えボタン | 新規作成／タイトルリライト。選択中のモードだけを表示し、両モードを左右に同時表示しない。記事作成 準備中は無効状態 |
| 配色 | 新規は青〜インディゴ、リライトは緑〜ティール。色に加えて画面名も明示 |
| 工程タブ | 新規は①〜④、リライトは①〜⑤。現在・未実施・完了・再確認が必要を文字で表示。各タブを後から自由に開いて確認できる |
| 本文領域 | 選択中の工程だけを表示。画像にあった下部の工程別折りたたみ一覧は削除 |
| 下部操作 | 「戻る」「次へ」を配置。「記事企画へ」など移動先がわかる文言にする |
| 選択情報 | 主・補助キーワードの要約を共通表示し、対象を見失わないようにする |

タブを開くだけではAI処理を実行せず、利用回数を消費しない。未実施の工程も閲覧でき、その工程の説明と未入力欄・未生成状態を表示する。分析・生成の実行時は必要な情報と最新状態を確認し、不足がある場合は該当項目と移動先を案内する。「次へ」はその工程で必要な必須入力を確認するが、任意項目の未入力では移動を妨げない。

同じページを開いている間は、工程移動や新規／リライトのモード切り替えでも、それぞれの入力・本文・分析結果・生成候補・最後に開いていた工程を保持する。元のモードへ戻ると作業中の工程を再表示する。ページの再読み込み・終了後はこれらを復元せず、初期状態から開始する。

新規作成とリライトのキーワードは連携せず、それぞれで設定する。モードを切り替えてもキーワードを他方へ転記しない。新規作成からリライトへキーワードを引き継ぐ操作（「このキーワードでリライト」）は将来対応とする。

AI処理中はモード変更と工程移動を許可しない。「新規作成」「タイトルリライト」の切り替え、工程タブ、戻る／次へ、履歴を開く操作などの移動操作を無効化する。処理対象の入力欄・クリア操作・再送信操作も無効化し、送信済み条件が途中で変わらないようにする。近くに「AI処理中は画面の切り替え・入力変更ができません」と表示する。成功・失敗・タイムアウト・補足待ちの応答で処理が終了したら操作を再び有効にする。内部の形式修正処理が続いている間は解除しない。移動の予約・自動実行は設けない。

合言葉を入力していない場合は、最初に合言葉入力画面を表示する。合言葉の通過後の初回表示とページ再読み込み後は「新規作成の①キーワード」を表示する。合言葉の仕様は「合言葉によるアクセス制限」に記載する。個人別のログイン画面は今回は作らず、将来対応とする。

## 合言葉によるアクセス制限

本人と許可した知人だけが使えるよう、共有の合言葉でアクセスを制限する。Vercelでインターネットに公開するため、初版で実装する。

| 項目 | 仕様 |
| --- | --- |
| 表示 | 合言葉を通過していないブラウザでは、アプリ名・合言葉の入力欄・「入る」ボタンだけを表示する。作業画面・履歴は表示しない |
| 合言葉の管理 | サーバーの環境変数で管理し、画面のコード・Git・ブラウザには含めない。変更はVercelの環境変数で行う |
| 入力欄 | 入力内容は伏せ字で表示し、「表示する」で確認できる。前後の空白は除いて判定する |
| 通過後 | 署名付きのCookie（JavaScriptから読めない設定）で通過済みを記録し、新規作成の①キーワードを表示する |
| 有効期間 | 通過から14日。期間内は再読み込みしても合言葉を求めない。期限切れ後は再入力を求める |
| 誤入力 | 「合言葉が違います」と表示する。同じ接続元で連続10回間違えた場合は20分間入力を受け付けず、再入力できるまでの待ち時間を表示する。正しく入力した時点で失敗回数をリセットする |
| 失敗回数の記録 | サーバー側の保存先で管理する。ブラウザのデータ削除でロックを解除できないようにする |
| 保護する範囲 | 画面に加え、URL読み込み・AI処理・利用回数の確認などのサーバー処理も、合言葉を通過していない場合は実行しない |
| 合言葉の変更 | 合言葉と署名用の鍵を変更すると、全員の通過記録が無効になり、再入力を求める |
| 利用回数 | 合言葉の入力は利用回数に含めない。利用回数のブラウザ識別は通過記録とあわせて管理する |
| 期限切れ時の作業 | 作業中に期限が切れた場合、AI処理の実行時に合言葉の再入力を求める。同じページ内の入力内容は可能な範囲で保持する |

個人別の招待・停止・利用制限は、将来の個別ログインで対応する。

入力を変えない閲覧だけでは再分析を要求しない。条件変更後の生成候補も閲覧・コピーできるが、「変更前の条件で生成」と表示する。タブ移動と分析・生成を明確に分ける。

## 新規タイトル画面

工程は「1 キーワード」「2 記事企画」「3 上位分析」「4 タイトル」の4つとする。

### 1 キーワード調査と選定

1. 上段にaramakijake・Ubersuggestへの外部リンクを置く。「外部サイトで調べる → 下の欄へ手入力」と案内する。
2. 候補は最大5件。キーワード・検索数・調査元・確認日を編集できる入力欄として表示する。検索数の未入力と0を区別する。
3. 各候補に「主に設定」「補助に追加」を置く。主は1つ、補助は任意で最大5個。候補からの選択に加え、補助の手入力欄も設ける。
4. 「主に設定済み」「補助に追加済み」を表示し、同じ語を主と補助の両方に登録しない。主の変更前には変更内容を示し、旧主を勝手に補助へ移さない。
5. 候補一覧の下に「候補を分析する」ボタンを置く。分析前・分析中・分析済み・条件変更後を区別する。入力しただけでAI分析が完了した表示にしない。
6. 結果には推定検索意図、関連性、記事の切り口と理由を表示する。検索数は手入力の調査値とし、AIで補完しない。ペルソナとの関連性は読者設定後に確認できるようにする。
7. 選択結果を主・補助の別枠に表示し、「選択したキーワードで記事企画へ」で進む。

検索数は任意であり、未入力だけを理由に次工程への移動を止めない。AI分析の実行ボタンには「AI利用 1回」と表示し、意図しない実行を避ける。

### 2 記事企画

テーマ、ペルソナ、読者の疑問・検索目的、構成・内容要約、強み、トーンを配置する。必須／任意と文字数をラベルで区別する。テーマは200文字、主・補助キーワードは各100文字、ペルソナ・疑問・要約・強みは各500文字の上限とする。

AI提案を呼び出す操作と、手動入力を区別する。推定項目には「AI推定・編集できます」と表示する。すでに手動編集した項目への再提案は、採用前に差分を確認できるようにする。

入力内容を「記事の制作方針」として一覧で確認できる。構成・内容要約が未入力の場合は「企画段階のタイトル候補」として進むことを案内する。

### 3 上位分析

Google検索への外部リンクと、上位最大5件の順位・表示タイトル・URL・確認日時の登録欄を配置する。「利用者が登録した検索上位」と明示する。

「上位タイトルを分析する」で傾向カテゴリを表示する。原則3〜5個とし、根拠が少ない場合は無理に増やさない。カテゴリを選ぶと根拠となる参考タイトルを表示する。

登録が1〜4件なら実件数で分析する。0件なら「上位タイトルの参考分析を省略して進む」と表示する。参考記事の本文を読んだという表現は使わない。

### 4 タイトル候補

「タイトルを10案生成する」を配置する。各候補を番号、30〜35文字のタイトル、実際の文字数、狙い、コピー操作の順に表示する。10案すべてを確認できるようにする。コピー成功・失敗はトーストで通知する。

参考上位の一覧は切り替え表示で確認できるようにし、すべての参考と候補を横に並べて圧迫しない。記事作成への将来導線は「準備中」として無効化する。

## タイトルリライト画面

工程は「1 記事読込」「2 キーワード・順位」「3 条件確認」「4 上位比較」「5 改善案」の5つとする。

### 1 記事を読み込む

上段に記事URLと「読み込む」、その近くに「読み込めない場合は本文を貼り付ける」を配置する。再読み込みで編集内容が置き換わる場合は確認し、キャンセル時は編集内容を保持する。

「読み込む」はページの取得と本文・見出しの抽出だけを行い、AI処理を実行せず利用回数を消費しない。取得または貼り付けた本文の下に「記事を分析する（AI利用 1回）」を別のボタンとして配置し、押した場合だけテーマ・要約・ペルソナ・検索目的・キーワード候補・強みなどをAIで推定する。本文が未入力または5,000文字を超えている間は「記事を分析する」を無効化し、理由を表示する。分析後に本文を変更した場合は、分析結果を再確認対象として表示する。

読み込み後に、現在のタイトル、本文、抽出見出しを確認・編集できるようにする。本文には「本文を広げて編集」を用意する。PCでは画面の約7割を使う重ね表示を開く。上部に「本文を編集」と現在の文字数／5,000文字、中央に大きな編集欄、下部に「キャンセル」「変更を反映」を配置する。

拡大編集を開く際に現在の本文を作業用にコピーし、「変更を反映」で通常の本文欄を更新して閉じる。「キャンセル」では拡大画面での未反映変更を破棄し、開く前の本文を維持する。未反映の変更がある場合、外側のクリックだけでは閉じない。閉じる・戻る操作でも変更が黙って失われないよう、反映または破棄の選択へ案内する。これは同じページ内の一時編集であり、下書きの永続保存ではない。

文字数は実際の編集内容に連動させ、通常欄・拡大欄とも上限5,000文字を表示する。超過時は切り捨てず編集を求め、上限内になるまで「変更を反映」を無効化する。キャンセルは可能とする。変更を反映した場合は、本文に依存する分析・生成結果を再確認対象とする。

本文欄の近くに「作業内容は一時保持です。モード・工程の切り替えでは残りますが、ページの再読み込み・終了でリセットされます。生成に成功した結果だけを履歴に残します」と常時表示する。併せて「画像内の情報は解析対象外。必要な内容は文章で補足」と案内する。

取得・推定した企画情報は後続工程で確認できる。推定情報を確定事実として表示せず、編集可能にする。

### 2 キーワードと順位

主・補助キーワードを表示する。主キーワードは手入力、または「記事を分析する」で推定したキーワード候補から選ぶ。選択済みのキーワードをURLの推定候補で自動上書きしない。別候補へ変更する操作は明示する。

「検索需要を調べる」は補助リンクとして配置する。現在順位は任意で、順位の数値と「未確認」「圏外」「未発見」を区別する。確認日時、検索条件、確認元、確認した範囲を記録できるようにする。Googleを別タブで確認する手動運用であることを明示する。

### 3 記事条件を確認

テーマ、ペルソナ、読者の疑問・検索目的、要約、強み、トーン、改善したい点を表示する。AI推定と利用者が修正した内容を区別する。現在のタイトルは100文字まで、要約は必須、改善点・補足回答は各500文字までとする。

本文とキーワードが一致しない場合は、該当項目の近くに理由と補足質問を表示する。AIの推定内容と本文を利用者が確認してから次へ進む案内を設ける。

### 4 上位タイトルと比較

現在のタイトルと対象キーワードを比較領域の上部に表示する。上位最大5件を順位・タイトル・URL・傾向カテゴリで比較し、共通点・相違点、本文で回答できる範囲を提示する。根拠のない不足論点を記事にあるものとして扱わない。

0件の場合は「上位タイトルとの比較を省略して進む」と案内する。現在順位が未入力でも進める。

### 5 改善タイトル候補

現在のタイトルを比較領域の上部に残し、その下を「改善候補 10案」「参考上位 最大5件」の切り替え表示にする。改善候補には文字数、狙い、改善ポイント、本文の根拠、コピーを表示する。固定表示する場合も画面を大きく覆わない高さにする。

本文にない数字・効果・実績などを加えない。参考上位は模倣や単純な言い換えに使わない。条件不足なら無理に10案を埋めず、補足を求める。

## 変更後の再確認

入力と以前の結果は保持し、どこまで確認し直す必要があるかを表示する。

| 変更した情報 | 表示・再確認対象 |
| --- | --- |
| 主キーワード | 検索意図・ペルソナ・企画方針・上位分析・生成タイトル。リライトでは順位と本文整合性も再確認 |
| 記事URL | 新URLの本文取得・条件確認・対象記事の順位・上位比較・生成結果。旧記事の情報を新記事のものとして表示しない |
| 本文・要約・ペルソナ・企画条件 | 関連する整合性確認と生成候補。変更していない調査値まで古い扱いにはしない |
| 参考上位タイトル | 傾向分類・上位比較・それを使った生成結果 |

表示文言は「キーワード変更後、未確認」「上位情報は変更前の条件です」「変更前の条件で生成」などとする。関連工程への再確認ボタンを付ける。変更しただけでAI処理を自動実行しない。

## 不足情報と任意項目

必須／任意のラベルは色だけに頼らず文字で表示する。必須の不足・空白・文字数超過は入力欄の近くに理由を表示する。補足質問では入力済みの内容を保持し、「補足を反映して再確認・生成」で続行する。

検索数、現在順位、補助キーワード、参考上位の登録は未入力でも進める。省略の影響がわかる説明を出し、任意情報の未入力だけで「次へ」を無効化しない。最終生成時は要件上の必須情報と整合性を確認する。

## 履歴と保存の案内

履歴は現在の画面に重ねるサブ画面として開き、PCでは画面の半分程度のサイズとする。閉じると元のモード・工程へ戻り、作業内容を保持する。一覧の主な表示内容はタイトルのみとし、長い企画条件・日時・キーワードの列は並べない。新規／リライトの区別は要件定義に従い最小限の種別ラベルで示す。「すべて／新規／リライト」の絞り込み、最新20件、21件目で最古の履歴を削除、個別・全件削除前の確認は維持する。

1回の生成成功を1件として扱う。一覧には代表タイトルを表示し、選択すると、その履歴で生成した10案を確認する詳細画面を開く。詳細表示は今回実装する。代表タイトルは初版では生成結果の先頭案を一覧用のラベルとして使い、利用者が採用したタイトルという意味にはしない。選択時の自動復元・本文の復元は実装しない。

履歴詳細は同じサブ画面内で一覧から切り替え、重ね表示を何枚も積まない。「一覧へ戻る」と「閉じる」を用意する。10案と各案の狙い・コピーを主に表示し、種別・生成条件・リライトの変更前タイトルや改善ポイントなどは保存内容の確認として表示する。閉じると元の作業画面・工程へ戻る。

下書き保存・入力の自動保存・作業復元は行わない。「下書きを保存」「下書き保存済み」「前回の続きから再開」といった操作・表示は置かない。生成結果には履歴の保存成否を表示する。LocalStorageへ永続保存するのは、生成成功時の履歴だけとする。

| 操作・対象 | 保存・保持の扱い |
| --- | --- |
| 工程タブ・モードの切り替え | 同じページ内の一時状態として入力・本文・修正・分析結果・工程を保持 |
| ページの再読み込み・終了 | 作業途中の内容と開いていた工程をリセット。短い入力も復元しない |
| AI分析だけ成功 | 作業中は表示するが、単独の履歴として保存しない |
| タイトル生成成功 | 1回を履歴1件として自動保存。再生成成功も新しい1件 |
| 生成失敗・補足待ち | 成功履歴を新規追加しない。表示中の入力は保持 |
| 履歴の保存失敗 | 失敗通知を出し、結果の閲覧・コピーは続けられる |

履歴には、生成日時・新規／リライト種別・主／補助キーワード・企画条件・内容要約・調査条件と調査値・参考上位情報・生成10案と各案の狙いを保存する。リライトは元記事URL・変更前タイトル・任意の順位記録と確認条件・改善ポイント・根拠の短い説明も保存する。本文全体・抽出見出し・本文の手動修正内容は保存しない。根拠の説明は生成結果の短い説明に限定し、本文全体の保存へ拡張しない。

履歴詳細で保存済み候補を閲覧・コピーできる。履歴を開くだけで現在の作業フォームへ条件を上書きしたり、作業を自動復元したりしない。履歴からリライトを再分析する案内には「本文は保存されていません。再分析する場合はURLを読み込むか本文を貼り付けてください」と表示する。要約だけで本文確認済みの状態にはしない。端末間同期、ブラウザデータ削除後の復旧は対象外。

画面共通で「作業途中の内容は保存しません。生成成功時の履歴のみ保存します」と案内する。入力クリアは現在のモードの一時入力をリセットする操作とし、履歴削除とは区別する。

### 履歴の自動保存タイミング

| 項目 | 仕様 |
| --- | --- |
| 自動保存 | 新規④／リライト⑤で10案の生成に成功し、件数・文字数・完全一致等の検証を通過した結果を受け取った時点で自動保存。採用・コピー・別の保存操作は不要 |
| 保存単位 | 1記事につき1件ではなく、生成成功1回につき1件。同じ記事で3回生成に成功した場合は3件。再生成は別件とし旧履歴へ上書きしない |
| 保存する条件 | その生成に使用した条件・調査情報・10案を保存。生成後の入力編集で保存済み履歴は変えない |
| 保存しない場合 | キーワード分析・記事分析・上位分析だけで終了した場合、生成失敗・タイムアウト・補足待ちでは新規履歴を作らない |
| 履歴が増えない操作 | 閲覧・コピー・工程移動・入力修正・内部形式修正・保存だけの再試行 |
| 保存通知 | 生成結果欄に「履歴に保存しました」を表示。トーストに加え、今回の結果の保存状態を確認できるようにする |
| 保存失敗 | 「履歴に保存できませんでした。このままページを閉じると今回の結果は失われます」と表示。結果の閲覧・コピーを維持し、「保存を再試行」を用意 |
| 保存の再試行 | 保持中の同じ生成結果を保存し直す。AI再実行・利用回数の消費・同じ生成結果の重複登録はしない |
| 保存上限 | 新規・リライト合計で最新20回分。21回目の保存成功時に最古の1件を入れ替える |

## 表示状態とスマートフォン対応

| 状態 | 画面上の動作 |
| --- | --- |
| 分析前 | 結果の代わりに操作説明。生成済みのようなサンプルを本番の結果欄へ出さない |
| 処理中 | 「本文を取得中」「記事を分析中」などの段階と進行表示。多重送信を防止。AI処理中はモード変更・工程移動・処理対象入力とクリアを無効化し、理由を表示 |
| 失敗 | 理由に応じた案内・再試行。入力を保持する |
| 利用上限 | 直近20分間10回の制限と再開までの待ち時間を表示。閲覧・コピー・工程移動は継続可能 |
| 条件変更後 | 旧条件の結果であることと再確認先を明示 |
| 取得対象外 | 画像やリンク先ページまで確認したかのような表示をしない |

### 処理中とエラーの表示位置

処理中は押したボタンを「分析中…」「生成中…」などに変え、進行表示と実際の処理段階を表示する。根拠のない残り秒数や完了率を表示しない。AI処理中のモード・工程移動、処理対象の編集・クリア・重複送信は禁止する。処理が終了したら操作を有効化し、入力を保持する。

| 状態 | 表示位置と操作 |
| --- | --- |
| 通信失敗・タイムアウト | 実行ボタンの近くに理由と「再試行」。前回の入力を保持し、手動で再実行 |
| 入力エラー | 該当する入力欄のすぐ下に具体的な理由。修正後に続行 |
| 不足情報・本文との不一致 | 同じ工程内に「確認が必要な点」、理由、質問と回答欄を表示 |
| 補足回答後 | 「補足して再確認」で続行。入力済みの他の情報は保持 |
| コピー成功・失敗 | トースト。タイトルはそのまま確認できる |
| 履歴保存失敗 | 保存できなかった旨を明示。結果表示とコピーを維持 |

補足回答は各500文字まで。AIを再実行する場合は利用回数の対象とし、質問を閲覧・回答するだけではAIを呼ばない。

### PCを優先した端末別の配置

主な利用環境はPCとし、PCでの入力・比較のしやすさを優先して設計する。スマートフォンにも対応し、PCの画面をそのまま縮小せず縦並びへ切り替える。

| 項目 | PC | スマートフォン |

| モード選択 | 上部の2ボタンで切り替え | 上部に2ボタンを並べる |

| タイトル候補 | タイトル・狙い・根拠を比較しやすい一覧 | タイトル・説明・コピーを1枚のカードへまとめる |

工程一覧は通常時に自由に開ける。AI処理中はスマートフォンでも同じ移動制限を適用する。

本文の拡大編集はスマートフォンでも利用できるようにする。固定操作やトーストが本文・入力欄を覆わない配置にする。ボタンに操作名を付け、キーボードで移動・選択できるようにする。

### 操作上の追加対策

| 項目 | 仕様 |
| --- | --- |
| ページ離脱 | 途中入力がある場合に再読み込み・ページ離脱時のブラウザ標準確認を可能な範囲で表示。工程・モード切り替えでは出さない。強制終了等では確認を保証できないため、途中非保存の案内を常時表示 |

| 代表タイトル | 一覧に「生成10案のうち先頭のタイトルを表示しています」と案内。採用済みを意味しない |

### 画面設計の確定状況

履歴詳細、本文拡大編集、スマートフォンの配置方針、処理中・エラー・補足質問の構成は本書のとおり確定。代表タイトルを先頭案とする扱い、履歴の同一サブ画面内での遷移などは本書で具体化した初版の設計値であり、タイトルの採用機能や作業復元機能を追加するものではない。具体的な余白・最大幅・端末幅に応じた切り替え位置は、PC優先の方針で詳細設計・実装時に調整する。

「候補を分析する」「企画を提案する」「記事を分析する」「上位タイトルを分析する」「タイトルを10案生成する」などのAI操作は直近20分間10回の利用制限に含める。画面の確認・コピー・外部リンク・タブ移動・「読み込む」（ページ取得のみ）・合言葉の入力は含めない。1つの実行操作内の形式修正1回は追加消費しない。処理中の表示・重複送信防止、ページ取得15秒・各AI処理60秒、通信失敗時の手動再試行は要件定義に従う。

## 画面の確認項目

- 工程ナビと戻る／次へだけで、新規・リライトを最後まで進める。
- 各工程を後から自由に閲覧でき、閲覧だけでAIの利用回数を消費しない。
- 新規とリライトが同時表示されず、モードを戻すと同じページ内の入力と工程が残る。
- AI処理中はモード切り替え・工程移動ができず、処理対象の編集・クリアも無効になる。
- 新規作成とリライトのキーワードは連携せず、モードを切り替えても他方へ転記されない。
- 合言葉を通過していない場合は合言葉入力画面だけが表示され、サーバー処理も実行できない。
- 合言葉の通過後14日間は再読み込みしても再入力を求めず、期限切れ後は再入力を求める。
- 連続10回の誤入力で20分間入力できなくなり、待ち時間が表示される。
- 初期表示・再読み込み後（合言葉の通過後）は新規①になり、個別ログイン画面は表示しない。
- リライトの「読み込む」では利用回数が減らず、「記事を分析する」を押した場合だけ1回消費する。
- 履歴は半画面程度の重ね表示になり、閉じても元の作業内容を保持する。
- 履歴の代表タイトルを選ぶと10案の詳細が開き、一覧へ戻る／元の作業へ戻るを使い分けられる。
- 本文の拡大編集はPCで約7割、スマートフォンで全画面となり、反映・キャンセルが正しく分かれる。
- スマートフォンで工程一覧・候補カード・履歴・本文編集が操作できる。
- 成功・失敗・タイムアウト・補足待ちの応答後に切り替えが再び可能となり、既存の入力は保持される。
- 検索数・調査元・確認日が編集可能だと見てわかる。
- 主・補助の登録状態、主変更時の動作、上限がわかる。
- 分析ボタンの実行前後と利用回数が区別できる。
- AI推定を手動で確認・修正できる。
- 拡大編集と通常編集で本文・文字数が一致する。
- 本文非保存の案内が本文欄と履歴再開時に表示される。
- 条件変更で入力が消えず、関連工程が未確認になる。
- 任意情報なし、参考1〜4件、参考0件でも所定の経路で進める。
- 現在タイトルと参考・改善候補が、小さい画面でも比較できる。
- 履歴の表示件数が実データと一致し、最大20件と区別される。
- ページ再読み込みで作業途中の入力・本文・分析結果がリセットされ、成功履歴だけが残る。
- 履歴を閲覧しても現在の作業を勝手に復元・上書きしない。
- コピー・保存失敗・利用制限・通信失敗を画面内で案内できる。

以上は設計上の確認項目であり、実装のテスト結果ではない。画像は配置検討用のサンプルであり、生成された文字・文字数・表示例より本書を優先する。下書き保存を連想させる案内は使用しない。
